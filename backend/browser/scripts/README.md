# Embedded browser page scripts

These scripts are injected into the web page's main world and run there; their arguments are passed in through template placeholders.

- Each `*.js` file is a single expression, `(() => { ... })()`, embedded into the Go binary with `go:embed` (`../page_scripts.go`).
- `pageScript(name, args...)` replaces `__ARG0__`, `__ARG1__`, ... with the JSON encoding of each argument, in one pass: `__ARG10__` is never read as `__ARG1__`, and placeholder-like text inside an argument value is never expanded again. A placeholder without an argument, or an argument without a placeholder, panics (the Go tests call every name). Each placeholder appears exactly once per file and never in a comment (enforced by `TestPageScriptPlaceholdersOccurExactlyOncePerSource`): JavaScript ends `//` comments at U+2028/U+2029, and a duplicate would hide a deleted real use from the unused-argument check. Assign it to a variable and reuse that.
- Names resolve to `<name>.js`, except the element actions (`click`, `fill`, `press_key`, `wait_for`, `select_option`, `set_checked`, `checked_state`, `hover`, `scroll`), which all live in `actions.js`. `set_checked` clicks at most once; when an ARIA widget has not updated `aria-checked` yet it returns `pending: true` and Go polls the read-only `checked_state` for up to 1 s. For those, Go passes `__ARG0__` = action name and `__ARG1__` = the argument array; `actions.js` dispatches to a function of that name, and the shared ref lookup and password/file guard (`resolveElement`, `guardSensitive`) live there once. Password inputs are blocked for every action; file inputs only for everything but `click`, which marks its result `fileInput: true` so Go waits for the native chooser (the user always picks the files), and `scroll` to a ref, which only brings the input into view. Only Go's `browser.click` opens the popup, file-chooser and download allowances; `set_checked` also calls `el.click()`, so a hostile page's handler may try to open a window or chooser from it, which the macOS gates then refuse. Composition happens inside the scripts, never by concatenating fragments in Go. The Go `pageScriptActions` table must match the function signatures (checked by `TestPageScriptActionArityMatchesActionsJS`); to add an action, add a function to `actions.js` and an entry to that table.
- `inspect.js` and `extract.js` repeat the ref lookup and guard from `actions.js`; keep their error messages identical.
- `snapshot.js` lists file inputs, hidden ones included, with only `ref`, `tag`, `type`, `role`, `name` (aria-label, title, or label text), `disabled`, `accept`, `multiple` and `selectedCount`, plus `frame`/`shadow` for their DOM location (never `inViewport`: they are usually hidden); never a value, file name or path. Password inputs are never listed.
- Snapshot state is `window.__mincodeAiRefs = { snapshotId, refs: Map<string, Element>, frames: Map<Document, Element> }`. `frames` maps each same-origin iframe document to its iframe element; `inspect.js` uses it to translate `rect` to the top viewport.
- `snapshot.js` walks the top document, same-origin iframes (`contentDocument` readable) and open shadow roots; closed shadow roots are unreachable. `maxElements` and `maxText` count across all of them; iframe text is appended to `text`. Elements in an iframe carry `frame` (`"0"`, `"0.1"`: the iframe's position among its document's iframes, then nested), elements in a shadow tree `shadow: true`, and every element except file inputs `inViewport` (its box, translated through the iframes' content boxes, intersects the top viewport and every enclosing iframe viewport). An iframe whose `contentDocument` throws or is null is cross-origin: listed as `{ref, tag, crossOrigin: true, origin, inViewport}` (origin is scheme, host and port of its `src`, empty for about:blank, srcdoc and data:) and never entered. `<select>` lists `options` (`value`, `label`, `selected`, `disabled`), at most 50 with `optionsTruncated: true` beyond, using the same label and limit as `select_option`'s error; a label or value longer than 300 code points is cut to 300 with `labelTruncated`/`valueTruncated`, and `select_option` accepts such a cut string (exactly 300 code points) as a prefix of a single option (several matches are an error); keep the two files in sync. Link `href`s (query and fragment removed) are cut to 300 characters with `hrefTruncated`; the title is cut to 300 code points with `titleTruncated`. Iframes and shadow roots are entered at most 32 levels deep; anything deeper is skipped and `truncatedElements` is set. Go additionally caps the serialized snapshot at 2 MB (`boundSnapshot`), dropping trailing elements and setting `truncatedElements`. Elements that scroll themselves (computed `overflow-x`/`overflow-y` of `auto`, `scroll` or `overlay` with content larger than the box on that axis; never `html`, `body` or the scrolling element) are listed with `scrollable: true`, for `scroll`'s `containerRef`. `input[type=hidden]` is never listed.
- A ref may belong to an iframe's document: actions build events (`new win.Event`, ...) and read computed styles in the element's own window (`el.ownerDocument.defaultView`), `press_key` without a ref follows focus into same-origin iframes and open shadow roots, and a ref whose document has no window any more (its iframe was removed or navigated) is stale. Hover coordinates are in the element's own frame viewport.
- Front-end tests run the same files in happy-dom through `vue-app/tests/browser-scripts/run-page-script.ts`, which applies the same rules and encodes arguments byte-for-byte like Go (`<`, `>`, `&`, U+2028, U+2029 escaped as `\uXXXX`). happy-dom does no layout, so tests mock `getBoundingClientRect`.
- `extract.js` (`browser.extract_content`; `__ARG0__`..`__ARG3__` = format `markdown`/`text`, maxChars, snapshotId, ref) returns `{title, url, content, truncated}`. Without a ref it renders the first visible `<main>`/`[role=main]`, else the outermost visible `<article>`s, else the element with the most non-link paragraph text (parent gets each paragraph's score, grandparent half). Inside, `nav`, `footer`, `aside`, `button` and the navigation/contentinfo/complementary roles are dropped (a ref that is one of them is still rendered), as are scripts, styles, media and every form control (never an input, textarea or select value), `hidden` or `display:none` subtrees, `visibility:hidden` text and closed `<details>` bodies. It walks the flat tree (open shadow roots, slot assignments), appends same-origin iframe documents' main content after the page (at most 32 iframe/shadow levels, 400 element levels; deeper content is skipped and `truncated` set), writes links as `[text](URL)` with the snapshot's href rules (http(s) only, no credentials, query or fragment, cut to 300 characters) and images as alt text only. Walking stops after twice maxChars of text; content is cut to maxChars without splitting a surrogate pair. The title is cut to 300 code points with `titleTruncated`, as in `snapshot.js`. Go caps the serialized result at 2 MB (`boundExtract`).
- `history_state.js` reads and optionally marks the document so `goHistory` can tell that a history step reached a new document even at the same URL; `history_go.js` (Windows only) steps WebView2 history through the page.
